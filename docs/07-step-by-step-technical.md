# Пошаговая инструкция: техническая часть Angel PC

## Что делаем
Сначала запускаем готовую статическую версию локально. Затем заменяем демонстрационный контент, заполняем документы, проверяем интерфейс и размещаем папку site на хостинге с доменом и HTTPS. Яндекс Метрику не подключаем. Автоматического приёма платежей и серверной формы в текущем объёме нет.

## Шаг 1. Распаковать проект
1. Скачайте angel-pc-project.zip.
2. В Windows нажмите правой кнопкой по архиву → «Извлечь всё».
3. Откройте распакованную папку angel-pc-project.
4. Проверьте наличие README.md, папок site и docs.
5. Не открывайте сайт прямо внутри ZIP: сначала извлеките все файлы.

## Шаг 2. Запустить сайт у себя
Простой способ: дважды нажмите site/index.html — откроется браузер.
Рабочий способ для проверки: откройте терминал в папке angel-pc-project и выполните:

```bash
python -m http.server 8080 --bind 127.0.0.1 --directory site
```

В Windows, если команда python не найдена, но установлен Python Launcher:

```powershell
py -m http.server 8080 --bind 127.0.0.1 --directory site
```

Откройте http://127.0.0.1:8080/ . Терминал оставьте открытым. Ctrl+C останавливает сервер. Если порт занят, замените 8080 на 8081 и откройте новый адрес.
Для этого проекта не нужны npm install, Node.js, React, PHP или база данных. Python нужен только для дополнительного способа локального просмотра.

## Шаг 3. Редактировать исходники
Откройте папку проекта в редакторе кода.
- site/index.html: заголовки, текст, ссылки, контакты и разметка.
- site/styles.css: цвета, размеры, адаптивная сетка и фон.
- site/app.js: массив products, фильтры и условные пороги подбора.
- site/legal/*.html: документы и реквизиты.
- site/legal/legal.js: уведомление о cookies.
Сохраняйте файлы в UTF-8. После изменения обновляйте страницу. При старом CSS в браузере используйте Ctrl+F5.
Сделайте копию папки перед существенными изменениями или ведите проект в Git. Удалённый репозиторий ещё не создан.

## Шаг 4. Заменить демонстрационные сборки
Запросить у продавца по каждой сборке: точное название, CPU, GPU, RAM, SSD, материнскую плату, блок питания, охлаждение, корпус, фотографии, цену и наличие.
В app.js обновить массив products. Не менять id без проверки привязанных сценариев. category определяет фильтры: gaming и/или work.
JSON в docs — только справка: редактирование его не обновит страницу.
В нынешних карточках цены отсутствуют. Для реальных цен потребуется добавить поле в products и вывод в шаблоне cards.innerHTML. До этого оставьте «Цена по запросу».
Пороги 120 000 и 230 000 — условные значения демонстрации, не цены. Подтвердите логику с продавцом; не обещайте соответствие бюджету на их основании.

## Шаг 5. Подготовить фотографии
1. Получить реальные фото и разрешение на использование.
2. Создать папку site/assets.
3. Сохранить оптимизированные фотографии в WebP или JPEG с понятными именами.
4. Заменить внешний адрес фона в styles.css на локальный, например url("assets/hero.webp"). Файл hero.webp нужно действительно добавить — его сейчас нет.
5. Для фото в карточках добавить image и alt в products, изменить шаблон .card-visual на img и задать в CSS размеры/object-fit. Это отдельная доработка: исходная версия использует текстовые обложки.
6. После локализации фона убрать устаревшие упоминания запроса к avatars.mds.yandex.net из политики, страницы cookies и текста уведомления.
Не заменять фон ссылкой на несуществующий файл. Визуальный референс из чата не является готовым набором фото для вёрстки.

## Шаг 6. Заполнить документы
В site/legal/privacy.html, terms.html и cookies.html найти все «ЗАПОЛНИТЬ» и внести фактические сведения.
Поля перечислены в docs/operator-fields.json. Этот JSON — список для передачи владельцу, не система автоматической подстановки.
Проверить ФИО ИП, адрес, email, домен, хостинг, обработку обращений и сроки хранения. После проверки и утверждения владельцем убрать предупреждения о проекте и согласовать дату редакции.
Не придумывать отсутствующие реквизиты. Не считать кнопку «Понятно» согласием на рекламу или регистрацию заявки.

## Шаг 7. Проверить сайт локально
- Навигация прокручивает к нужным разделам.
- Фильтры показывают 3 / 3 / 2 карточки соответственно.
- Каждая кнопка «Подробнее» открывает нужную сборку.
- Диалог закрывается крестиком и Escape; прокрутка после закрытия работает.
- Подбор: 110 000, 120 000, 220 000 и 230 000 ₽, разные задачи.
- Смена параметров убирает старый результат.
- Текст обращения можно изменить и скопировать.
- Telegram открывается; текст пользователь отправляет сам.
- Телефон, канал и Avito ведут на нужные адреса.
- Все три документа открываются, возврат ведёт на главную.
- «Понятно» скрывает уведомление; после перезагрузки оно появляется вновь — это ожидаемое поведение без хранения выбора.
- На телефоне нет горизонтальной прокрутки; меню работает.
- При отключённом JavaScript документы и контакты доступны, интерактивный каталог не работает.
- В инструментах разработчика проверить Console и Network: нет ошибок кода, потерянных файлов и неожиданной аналитики.

## Шаг 8. Выбрать домен и размещение
Нужен статический хостинг с HTTPS; отдельный сервер приложения текущему сайту не требуется.
Провайдер, домен и аккаунт ещё не выбраны. Конкретные DNS-записи берутся из панели выбранного хостинга, а не из примера или предположений.
До размещения проверить пригодность инфраструктуры для фактической обработки данных: журналы, cookies, расположение и доступы. Это влияет на окончательный текст политики.

## Шаг 9. Загрузить сайт
В корень веб-сайта загрузить содержимое site: index.html, styles.css, app.js, legal и assets, если добавлены.
Не загружать весь архив в публичный корень, не публиковать docs, резервные копии и служебные файлы.
Проверьте, что index.html находится непосредственно в корне сайта, а не случайно на один уровень глубже.
В панели хостинга связать домен с сайтом, у регистратора прописать выданные DNS-записи. После применения записей активировать сертификат HTTPS и перенаправление HTTP → HTTPS средствами провайдера.
SSH, пароли и токены не входят в архив и не должны храниться в публичных исходниках.

## Шаг 10. Проверить опубликованный домен
Повторить основные сценарии шага 7 на реальном адресе. Проверить HTTPS, отображение картинок, прямое открытие /legal/privacy.html, мобильный вид, отсутствие ошибок 404.
Проверить cookies и HTTP-заголовки: хостинг может устанавливать свои cookies, даже если JavaScript их не создаёт. Обновить документы под фактический результат.
Сохранить копию опубликованной версии и записать дату, адрес и изменения для возможного отката.

## Если позже нужен сбор заявок на самом сайте
Это отдельный следующий этап: endpoint на сервере, валидация, защита от спама, безопасное хранение и доставка обращения, ограничение доступа, сроки удаления и фиксация согласия при выбранном основании. Секрет Telegram-бота хранить только на сервере. Не помещать токен в app.js. Текущая клиентская форма сервером не становится после добавления кнопки «Отправить».
